## Corrections that change meaning

- Owners tab: "metadata designation, confers no administrative capability" → owners can manage the application's SSO, provisioning and user assignment and add owners (Application Administrator permissions scoped to the app), and can act as the app beyond their own access. Source: overview-assign-app-owners.
- Consent execution (Workflow B step 5 and catalog): Help Desk activates a privileged role → the IGO or delegated authority activates the role that can grant: Privileged Role Administrator for Graph application permissions, Cloud Application Administrator or Application Administrator otherwise. Source: grant-admin-consent.
- Consent revocation (step 3 and catalog): Help Desk removes the grant → at least Cloud Application Administrator revokes on the Admin consent tab; user-consent grants are removed through Graph or PowerShell. Source: manage-application-permissions.
- `Mail.ReadWrite.All` (application) → `Mail.ReadWrite` (application); the permission doesn't exist. Source: Graph permissions reference.
- Critical-scope trigger "\*.All at application level" → the Critical rating in the risk table, which also catches `Mail.ReadWrite` and `Mail.Send` application permissions. Source: Graph permissions reference.
- Consent phishing "specifically targets Admin Consent" → tricks users into granting permissions; reaching a consent-capable admin yields a tenant-wide grant. Source: protect-against-consent-phishing.
- ServiceNow automation identity: Entra "service account" → OAuth 2.0 app registration used by the Entra ID spoke (also IA-5 row wording). Source: ServiceNow Entra ID spoke page.
- ServiceNow spoke quotation replaced with the page's actual sentence; Integration Hub subscription requirement added. Source: ServiceNow Entra ID spoke page.
- Audit categories: break-glass "SignInLogs" → sign-in logs; user consent setting changes "Policy" → AuthorizationPolicy ("Update authorization policy"). Sources: reference-audit-activities, configure-user-consent.
- Resolved by the author's decision (Oct 27, 2026): the catalog's New Application Registration and Access Group Creation rows, the RACI registration row, the Group creation section and the Group Creator role now assign execution to Identity Engineering, because the Help Desk PAG holds no role that can do either (adding an enterprise application needs Cloud Application Administrator or Application Administrator — Learn "Quickstart: Add an enterprise application," Prerequisites, accessed Oct 27, 2026). The admin guide, Helpdesk Flow, implementation path and the module's `GroupCreation` row (now `TriageEscalateOnly`) were aligned.
