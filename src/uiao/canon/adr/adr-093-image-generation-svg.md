# ADR-093: Image Generation moves to committed Claude-authored SVG (NanoBanana retired)

## Status

**PROPOSED** — June 4, 2026

## Context

UIAO figures were generated by the Google **Gemini 2.5 Flash Image** model — the
"NanoBanana" pipeline — driven from `[IMAGE-NN: …]` / `[DIAGRAM-NN: …]`
placeholders and `fig-alt` prompts, orchestrated by
`scripts/generate_images.py` and `.github/workflows/image-gen.yml`
(ADR-071/072 publication policy; AGENTS.md §7).

The model is a **generative raster** engine, and that is the problem. Across the
corpus it bakes **spelling and label errors directly into the pixels** —
confirmed examples in shipped Book_01 figures include `Cloud: decmposed point
tools`, `MICROSFT CLOUD STACK` (×2), `distinged name`, `travseral`, `policy
inherts down the tree`, `no inhertance`, `device-princial`. These are not
fixable downstream; the only remedy is re-rolling the prompt, which frequently
reproduces a *different* text error. For federal-grade, customer-facing
deliverables this is an unacceptable, recurring defect.

The Gemini coupling is shallow: a single `generate_image()` call site in
`generate_images.py` (mirrored in `regenerate_local_images_from_figalt.py` and
`generate_canon_images.py`). Everything else — placeholder harvesting, the
canonical `image-registry.yaml`, `.png.json` sidecars, the
`.image-manifest.json`, `replace_placeholders.py`, and the Quarto render — is
backend-agnostic.

## Decision

**1. SVG is the source of truth; PNG is a build artifact.**
Each figure is a committed `<name>.svg` authored by **Claude Code** against the
house style. The sibling `<name>.png` is produced by rasterizing the SVG and is
the artifact the docs reference. Because the diagram is vector text, **the text
is always exactly what the source says** — there is no generative step at render
time, so the class of NanoBanana defects is structurally impossible.

**2. CI only rasterizes — no AI, no API key.**
`scripts/render_svg_images.py` walks committed `*.svg`, rasterizes each to PNG
(prefers `cairosvg`; falls back to Playwright/Chromium for `<foreignObject>` or
web fonts), and writes the **existing** sidecar schema with
`generator = "claude-svg-v1"`. The `GEMINI_API_KEY` secret and the
`google-genai` dependency are removed.

**3. The placeholder/registry/sidecar/manifest contract is unchanged.**
`render_svg_images.py` imports `write_sidecar` / `embed_png_metadata` /
`sha256_*` from `generate_images.py`, so sidecars and PNG `tEXt` provenance are
byte-identical in shape. `replace_placeholders.py`, `image-registry.yaml`, and
`quarto.yml` need no changes. (One latent bug is fixed in passing: the PNG is
re-hashed *after* `tEXt` embedding so the sidecar `sha256` matches on-disk
bytes.)

**4. House style is centralized.**
`src/uiao/canon/svg-style/` holds `palette.json` (navy `#0D1B2E`, teal
`#1E8C8C`, amber `#D4A017`, mid-blue `#2E75B6`, grey `#5A5A5A`, white
background), a 16:9 and 1:1 base template, and `STYLE.md`. Previously the palette
lived only inside prompt bodies; it is now a single referenced source.

**5. Authoring + cache.**
Freshness is the SHA-256 of the SVG text (LF-normalized), recorded in the
sidecar `prompt_sha256`; an unchanged SVG with an existing PNG is skipped.

## Consequences

**Positive**
- Eliminates baked-in text errors — the original motivation.
- Deterministic, diff-reviewable figures; the SVG is human/agent-editable.
- No paid API call, no API-key secret, no per-figure generation cost or rate limit.
- Diagrams become first-class, versioned source, not opaque binaries.

**Costs / trade-offs**
- Authoring shifts from "write a one-line prompt" to "author/edit an SVG"
  (Claude Code does this; the style library makes it mechanical).
- A rasterizer (`cairosvg`, or Playwright/Chromium) is now a build dependency.
- Pure-vector SVG is unsuitable for **photographic/artistic cover-art**; those
  registry entries (`visual_style: cover-art`) are out of scope here and flagged
  for separate handling rather than degraded into flat vector.

**Rollout**
- This change ships the pipeline, style system, CI, and **Book_01** figures as
  the proof. Remaining books and canonical diagram entries are regenerated in
  batched follow-up PRs using the same machinery. Existing NanoBanana PNGs remain
  valid until replaced by their SVG-sourced versions.

## Alternatives considered

- **Claude API → SVG at build time.** Keeps the one-click flow but reintroduces a
  generative step, an `ANTHROPIC_API_KEY` secret, and run-time variability.
  Rejected: committed SVG is more reliable and fully reviewable.
- **Regenerate via NanoBanana with better prompts.** Rejected: text errors recur;
  the failure mode is intrinsic to generative raster.
- **Mermaid / PlantUML.** Mermaid previously broke Quarto CI (reverted); neither
  matches the house visual style. Rejected.
