The sites listed here are the entire scope of the exemption. Adding a site is a scope change and requires return to the Authorizing Official — so this register is a controlled document, and its version is the thing the signed memo refers to.

This register is the SC-7(4) exception record itself, not a supporting annex to it. SC-7(4) requires each exception to the traffic-flow policy to be documented with its supporting mission need and the duration of that need, and requires those exceptions to be reviewed on a stated cadence and removed when the need no longer holds. Table A1 carries those fields; A2 and A3 carry the network and readiness detail beneath them. A register that lists circuits but records no mission need and no expiry cannot evidence the control the memo claims.

One row per site, where A2 is one row per circuit: the mission need is a property of the site, the egress range is a property of the circuit.

Two fields are worth writing carefully. Mission need restated from the program justification is not a site-level need — if the same sentence would serve every row, none of them is answering the question. Expiry may be a date or a condition ("until the site is migrated to the SASE fabric"), but it may not be blank: an exception with no end is a permanent change to the traffic-flow policy, which is a different decision from the one the memo asks for.

Completion rules for egress ranges

R1–R5, referenced by the admission checklist

These are the errors that actually occur, in the order they occur. Each one produces a fabric that appears configured and attributes traffic to the wrong place.

  1. Record the post-NAT public address the branch presents to the internet — not the WAN interface address, and not the inside pool. The address Microsoft and your probe endpoints observe is the one that identifies the circuit. An interface address recorded here silently mis-attributes every measurement from that site.

  2. Give each circuit a unique range. If two circuits at a site share a NAT pool, per-circuit attribution is not possible. Fix the NAT design before listing the site, or accept that path comparison at that site is meaningless and record why.

  3. Ranges must be static and assigned to the agency for the life of the exemption. Dynamically assigned or ISP-rotated addresses do not qualify. A changed egress address moves the site outside the approved scope without anyone making a decision to move it.

  4. Verify each range from the branch itself before listing it, not from documentation or the ISP order. Recorded ranges and deployed ranges diverge over time. The site is the authority; the record is not.

  5. Where IPv6 is enabled on the circuit, list the IPv6 range too. An IPv6-capable client egressing on an unlisted range is outside the recorded scope even though the site is listed.

Dates rather than ticks throughout. A tick records an intention; a date records an event, and a reviewer can check it.

TRv2 device signaling is the date tenant restrictions v2 was confirmed in force at the site from the endpoint rather than the proxy. Bypassing the proxy removes the header-injection path, so unless the device-side path is configured and verified, the site is cut over with tenant restrictions silently unenforced. Record alongside it the device and browser population the Group Policy path does not cover — it reaches Office applications, Universal Windows Platform .NET applications and Microsoft Edge, and nothing else.

Admission checklist

All of the following must be true before a site is listed in Table A1. A site that fails any line is not ready to be in scope, and adding it later is a scope change.

Egress ranges verified from the site and satisfying completion rules R1–R5.
Table A1 complete for this site: a site-specific mission need, a start date, and an expiry or ending condition that is not blank.
Endpoint feed confirmed as Worldwide (+GCC) — not the DoD or GCC High instance.
Probe endpoint resolves and responds from this branch, not only from the datacenter.
Name resolution for Microsoft 365 occurs local to this branch's egress — no conditional forwarder returns these queries to a core resolver. Central resolution defeats local egress silently and the probes will not report it.
ThousandEyes agent registered to the government instance, and absent from the commercial console.
Tenant restrictions v2 signaled from the endpoint and verified in force, since the proxy path goes with the bypass — with the device and browser population it does not cover enumerated rather than assumed empty.
Pre-cutover baseline captured and retained — the one step that cannot be recovered afterward.
Branch telemetry reaching CLAW under the reporting pattern named in the memo.
Router sized for the finished architecture, including UTD if the capability transfer places it here.
Revert owner named, reachable, and able to act within one shift without an approval cycle.
Handling

Completed, this register is a map of the agency's branch egress: public addresses, circuit topology, per-site user counts and which sites have reduced inline inspection — and, with Table A1, why each one was granted it. Handle and mark it under the agency's own rules for network architecture information, and check before circulating it more widely than the signature chain.

The example rows use 203.0.113.0/24, 198.51.100.0/24 and 192.0.2.0/24 — reserved for documentation under RFC 5737 and safe to publish. Delete them once real rows exist, so no reader has to work out which is which.

Change log

Record every scope change here with its date and the AO decision that authorized it. The register version cited in the signed memo is the authoritative scope; a later version without a corresponding decision is a finding, not an update.

Record the SC-7(4) reviews here too, on the cadence the memo states, including the reviews that change nothing. The control requires exceptions to be reviewed and removed when the supporting need lapses; a register showing no reviews evidences no reviews, whatever happened in practice.
