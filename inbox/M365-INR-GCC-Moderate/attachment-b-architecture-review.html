What this determination is, and is not

This document records the architecture review's finding that the design is TIC 3.0 conformant and that campus policy enforcement point capabilities have been accounted for at the branch. It does not accept risk. The single item requiring the Authorizing Official's decision — the Optimize-category inspection exemption, sought as a documented SC-7(4) traffic-flow exception — is referred to them in the covering memo. Keeping those two decisions separate is what allows each signer to answer a question that is actually theirs.

B1 — Security pattern classification

The Branch Office Use Case defines three patterns. An agency may implement a subset. Classification is not bookkeeping: it determines which policy enforcement point capabilities apply, and a misclassification here propagates into every row of B2.

Branch Office to Cloud Service ProviderProposed Branch users reaching an agency-sanctioned CSP. Microsoft 365 is a sanctioned service under [reference], which places locally egressing Optimize traffic in this pattern.
Branch Office to Web Generic internet destinations. Selecting this pattern for Microsoft 365 pulls in a general web-proxy capability set whose inspection expectations are incompatible with the Optimize category's purpose.
Branch Office to Agency Campus Branch access to internal resources. Applies to the site's other traffic and is unchanged by this design; recorded here for completeness.

Universal Security Capabilities

These are not PEP capability groups and do not belong in the table above. The catalog treats universal capabilities as enterprise-level and expected in every use case, whereas PEP capabilities apply or not according to the use case scope. Conflating the two is a common way for a capability-transfer register to look complete while leaving the enterprise layer unexamined.
