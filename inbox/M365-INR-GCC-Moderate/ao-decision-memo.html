Decision requested

Approve a documented traffic-flow exception under SC-7(4) exempting the Microsoft 365 Optimize endpoint set from TLS break-and-inspect at branch direct-internet egress, for the [N] pilot sites listed at Attachment A.

The controls the exception punctures are named at clause 3. One of them — tenant restrictions v2 — cannot be re-established at the network layer once the proxy is bypassed and has to be re-signaled from the endpoint; clause 4 states how, and what it does not cover. Compensating controls are at clause 6 and the reversal commitments at clause 7.

Background

Microsoft 365 Informed Network Routing, which supplies Microsoft's network-quality signal to SD-WAN path selection, is not available to GCC Moderate tenants. Microsoft states this directly in its product documentation, and the agency's own substrate encodes it as a machine-enforced contract fixture — FINDING-001 — so the constraint is designed for rather than missed. Commercial and sovereign cloud feature parity is sequenced rather than simultaneous; the capability is absent from all five of the non-commercial clouds Microsoft names.

The agency's Catalyst SD-WAN fabric will therefore steer Microsoft 365 traffic using Cloud OnRamp for SaaS probe measurements alone, with local direct internet access at branch sites. This is a product-availability limitation in the government cloud, not a FedRAMP or authorization boundary matter, and it requires no FedRAMP action.

What is being sought: an SC-7(4) traffic-flow exception

This is not a general risk acceptance. It is a documented traffic-flow exception under SC-7(4), and it carries that control's discipline: a named exception with its supporting mission need, reviewed on a stated cadence, with the SD-WAN steering log serving as the enforcement evidence that the exception's boundaries hold.

The distinction matters at assessment. Documentation alone is not a compensating control. What makes the carve-out defensible is that the DPI classification steering an Optimize flow around the overlay is itself a logged, per-flow record of which traffic rests on application-layer encryption and which rides the tunnel.

Controls affected, named

Traffic to Microsoft 365 Optimize endpoints will egress locally at pilot branch sites without traversing the campus policy enforcement point. Naming what that punctures, rather than describing it as "inspection forgone":

  • SI-3 — no secure web gateway inline malicious-code inspection on the bypassed flows.
  • SI-4(10) — no visibility into the content of encrypted communications. The TLS break-and-inspect that satisfies this control for proxied flows is absent by design here.
  • AC-4 — no CASB information-flow enforcement on those flows.
  • AU-3, and AU-12 by reference — records are still generated for the bypassed flows, so what degrades is their content: five-tuple plus steering metadata over encrypted media, not user, device, application, action and data type. AU-12 requires generation with the content AU-3 defines, so naming AU-3 states the degradation precisely.

SC-8 is explicitly not a gap, and the memo says so to forestall the obvious challenge. Optimize flows carry their own FIPS-validated encryption — TLS, and SRTP for Teams media — and the IPsec overlay continues to encrypt every flow that does not. This is the per-flow closure the coverage doctrine already concedes, not a new hole.

This follows Microsoft's published connectivity guidance, which recommends bypassing inspection for these endpoints because they are secured at the client and service ends and because re-encrypting inspected traffic introduces protocol errors and risk of its own. The agency is implementing the vendor's documented design, not departing from it.

The control that moves off the network path: tenant restrictions

Tenant-to-tenant exfiltration over an Optimize-categorized path is the case an assessor will construct against this exemption, and it should be answered in the record rather than discovered at assessment.

The answer is that tenant restrictions v2 does not depend on the proxy. Microsoft documents three enforcement paths for a single cross-tenant access policy, and proxy header injection is the weakest of them: it signals at the authentication plane only and does not reach the data plane. The agency therefore does not lose this control by bypassing the proxy — it re-signals it from the endpoint, where the coverage is better than what the proxy provided.

  • Windows Group Policy signaling on corporate-owned devices — no proxy required, and the only path that carries both authentication-plane and data-plane protection. Policy evaluation remains in the cloud; the device supplies the signal. This is the agency's primary path.
  • Universal tenant restrictions via Global Secure Access — authentication plane on every operating system, browser and form factor, and data plane for Microsoft Graph only. Availability in the government cloud is unconfirmed, so this is a fallback rather than a plan.
  • Proxy header injection — the path being given up, and the one the exemption removes. Authentication plane only.

Two limits are stated rather than glossed. The Group Policy path covers Office applications, Universal Windows Platform .NET applications and Microsoft Edge; non-Edge browsers and non-Windows devices are not covered by it, and any such population at a pilot site is in scope for the exemption but not for this compensating control. Parts of tenant restrictions v2 remain in preview. This control is therefore compensable but not automatically compensated: it is in force only if the device-side signaling is configured and verified before cutover, which clause 6 records as a precondition and clause 8 as a return trigger.

Scope, and why it is bounded

  • Endpoints: the Optimize category only, enumerated from the Microsoft 365 IP and URL web service, Instance=Worldwide — the instance serving GCC. The Allow and Default categories are not in scope and remain subject to existing inspection.
  • Change control: the set is machine-readable and published, with additions released 30 days before they become active. Scope is reviewed on the feed's monthly update cadence — which is also the SC-7(4) review cadence.
  • Sites: the pilot sites at Attachment A only, recorded per circuit rather than per site. Fleet expansion is not authorized by this memo.
  • Architecture: classified under TIC 3.0 as Branch Office to Cloud Service Provider. Architecture review sign-off at Attachment B.

Reversal

Steering reverts per site within one shift by network operations, without an approval cycle. Reversion returns traffic to backhaul through the campus policy enforcement point, restoring the prior enforcement posture rather than degrading it.

Withdrawal of the exception is a tracked step of any such rollback. The agency commits that the exception will not remain in force at sites returned to backhaul — leaving it in place would retain the accepted risk while forfeiting the performance it was accepted for.

Return to the Authorizing Official

The system owner will return for a further decision if: the exception scope widens beyond the Optimize category; sites are added outside Attachment A; a compensating control named above is found not to be in place, including tenant restrictions v2 device-side signaling at a site being cut over; the SC-7(4) review finds the steering log no longer evidences the exception's boundaries; or the exception is withdrawn during a rollback.

Matters not yet confirmed

Disclosed for completeness; none blocks this decision, and each is tracked to closure:

  • Whether ThousandEyes Enterprise Agents hosted on Catalyst routers can register to the government platform instance. Standalone agent deployment is the fallback and does not affect this exception.
  • Microsoft publishes no rationale for the GCC limitation. None is required for this decision — the limitation is documented and the exception does not rest on why it exists.
  • Whether Global Secure Access, and therefore universal tenant restrictions, is available to this tenant in the government cloud. The Windows Group Policy path at clause 4 does not depend on the answer; the fallback does.
  • Engineering detail in the supporting material was assembled from vendor and CISA documentation accessed indirectly, and is being reconfirmed against current versions — including the TIC 3.0 Security Capabilities Catalog revision cited at Attachment B.
